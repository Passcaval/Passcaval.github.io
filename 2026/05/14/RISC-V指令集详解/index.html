RISC-V指令集详解

发表于2026-05-14|更新于2026-05-26|computer science
|浏览量:

前言

RISC-V（发音为”risk-five”）是一个基于精简指令集（RISC）原则的开源指令集架构（ISA），由加州大学伯克利分校的 Krste Asanović 教授团队于 2010 年发起。与 x86、ARM 等商业 ISA 不同，RISC-V 完全开放、免费，任何人都可以设计、制造和销售 RISC-V 芯片和软件，无需支付授权费用。本文将深入解析 RISC-V 指令集的各个层面。

一、RISC-V 的设计哲学

1.1 精简核心

RISC-V 继承 RISC 哲学的精髓：

  • 指令定长：基础指令固定 32 位（RV32/RV64），压缩指令 16 位（RV64GC 中的 C 扩展）
  • Load-Store 架构：只有 load/store 指令访问内存，运算类指令仅操作寄存器
  • 大量通用寄存器：32 个整数寄存器（x0-x31），32 个浮点寄存器（f0-f31）
  • 简洁的寻址模式：仅寄存器间接寻址和立即数偏移寻址

1.2 模块化设计

RISC-V 最大的创新在于模块化——它不是单一标准，而是一个核心基础加上可选的扩展：

扩展名 全称 说明
I Base Integer 基础整数指令集（必须）
M Multiply/Divide 整数乘除法
A Atomic 原子操作指令
F Single-Precision Float 单精度浮点
D Double-Precision Float 双精度浮点
C Compressed 16 位压缩指令
B Bit Manipulation 位操作
V Vector 向量扩展
Q Quad-Precision Float 四精度浮点

1.3 寄存器约定

RISC-V 规范对 32 个通用寄存器的用途有明确的软件约定（ABI）：

寄存器 ABI 名称 用途 保存者
x0 zero 恒为 0 —
x1 ra 返回地址 调用者
x2 sp 栈指针 被调用者
x3 gp 全局指针 —
x4 tp 线程指针 —
x5-x7 t0-t2 临时寄存器 调用者
x8 s0/fp 帧指针 / 保存寄存器 被调用者
x9 s1 保存寄存器 被调用者
x10-x17 a0-a7 函数参数 / 返回值 调用者
x18-x27 s2-s11 保存寄存器 被调用者
x28-x31 t3-t6 临时寄存器 调用者

二、基础整数指令集 (RV32I)

RV32I 包含 40 条独特的指令，分为 6 种指令格式（R/I/S/B/U/J）。所有指令都是 32 位宽。

2.1 指令格式总览

各字段含义：

  • opcode (7 bits): 指令大类操作码
  • rd (5 bits): 目标寄存器编号
  • rs1 (5 bits): 第一个源操作数寄存器编号
  • rs2 (5 bits): 第二个源操作数寄存器编号
  • funct3 (3 bits): 功能码（细化操作类型）
  • funct7 (7 bits): 额外功能码
  • imm (不同长度): 立即数字段，编码方式因格式而异

2.2 R-type（寄存器-寄存器指令）

R-type 指令从两个寄存器读取操作数，结果写入目标寄存器。

指令列表：

指令 功能 C 语言等价
add rd, rs1, rs2 加法 rd = rs1 + rs2
sub rd, rs1, rs2 减法 rd = rs1 - rs2
sll rd, rs1, rs2 逻辑左移 rd = rs1 << rs2[4:0]
slt rd, rs1, rs2 有符号小于则置 1 rd = (rs1 < rs2) ? 1 : 0
sltu rd, rs1, rs2 无符号小于则置 1 rd = ((unsigned)rs1 < (unsigned)rs2) ? 1 : 0
xor rd, rs1, rs2 按位异或 rd = rs1 ^ rs2
srl rd, rs1, rs2 逻辑右移 rd = rs1 >> rs2[4:0]
sra rd, rs1, rs2 算术右移 rd = (signed)rs1 >> rs2[4:0]
or rd, rs1, rs2 按位或 rd = rs1 | rs2
and rd, rs1, rs2 按位与 rd = rs1 & rs2

2.3 I-type（寄存器-立即数指令）

I-type 指令包含一个 12 位符号扩展的立即数。

运算类指令：

指令 功能
addi rd, rs1, imm 立即数加法

sltiu rd, rs1, imm 无符号小于立即数则置 1

lbu rd, offset(rs1) 加载字节（零扩展）

2.4 S-type（存储指令）

S-type 指令将寄存器值写入内存，立即数为 12 位（拆分为两段编码）。

指令 功能
sb rs2, offset(rs1) 存储字节
sh rs2, offset(rs1) 存储半字
sw rs2, offset(rs1) 存储字

2.5 B-type（条件分支指令）

B-type 指令根据两个寄存器的比较结果决定是否跳转。立即数存储编码方式比较特殊：第 0 位始终为 0（因为 RISC-V 跳转目标必须对齐到 2 字节边界），因此 imm[11:0] 实际编码为 imm[12|10:5|4:1|11]。

指令 功能 跳转条件
beq rs1, rs2, offset 相等则跳转 rs1 == rs2
bne rs1, rs2, offset 不等则跳转 rs1 != rs2
blt rs1, rs2, offset 小于则跳转 rs1 < rs2（有符号）
bge rs1, rs2, offset 大于等于则跳转 rs1 >= rs2（有符号）
bltu rs1, rs2, offset 小于则跳转 rs1 < rs2（无符号）
bgeu rs1, rs2, offset 大于等于则跳转 rs1 >= rs2（无符号）

RISC-V 的一个显示设计决策：bge 和 blt 是独立指令，而不是”用一条 compare 指令设置标志位后再用 jump 判断”。这减少了指令条数的同时避免了标志寄存器带来的超标量设计复杂度。

2.6 U-type（上位立即数指令）

U-type 指令编码一个 20 位的立即数（占指令的高 20 位，低 12 位为 0）。

指令 功能
lui rd, imm 加载上位立即数 rd = imm << 12
auipc rd, imm 立即数与 PC 相加 rd = PC + (imm << 12)

为什么需要 LUI？ 由于 RISC-V 固定 32 位指令长度，无法将 32 位立即数直接编码。构造 32 位的完整立即数需要两步：先用 lui 设置高 20 位，再用 addi 补充低 12 位：

auipc 主要用于位置无关代码（PIC），将 PC 相对地址的高位计算出来，与后续指令组合实现任意 PC 偏移寻址。

2.7 J-type（无条件跳转指令）

指令 功能
jal rd, offset 跳转并链接：rd = PC + 4，然后 PC = PC + offset

C 语言函数调用的本质就是 jal ra, func + jalr x0, 0(ra) 的组合。RISC-V 用一条指令完成”保存返回地址 + 跳转”。

  • Switch/Case：从跳转表读取地址后跳转

三、乘除法扩展 (M)

RISC-V M 扩展增加了 8 条乘除法指令。

3.1 乘法指令

指令 功能
mul rd, rs1, rs2 有符号乘法（低 32 位）
mulh rd, rs1, rs2 有符号乘法高 32 位
mulhu rd, rs1, rs2 无符号乘法高 32 位
mulhsu rd, rs1, rs2 有符号 × 无符号，高 32 位

3.2 除法与取余

指令 功能
div rd, rs1, rs2 有符号除法
divu rd, rs1, rs2 无符号除法
rem rd, rs1, rs2 有符号取余
remu rd, rs1, rs2 无符号取余

除零行为：RISC-V 不抛出异常，而是返回特定值——div 返回全 1（即 -1），rem 返回被除数。

溢出行为：唯一溢出情形是 INT_MIN / -1（有符号除法的 −2³¹ ÷ −1），RISC-V 此时返回被除数，而非触发陷阱。

四、原子操作扩展 (A)

A 扩展提供两类指令：原子读-改-写（LR/SC）和原子内存操作（AMO）。

4.1 Load-Reserved / Store-Conditional

LR（Load-Reserved）从内存读取值并在该地址上注册一个”保留”。SC（Store-Conditional）仅在保留仍有效时才写入内存——否则失败。

4.2 原子内存操作 (AMO)

指令 功能
amoswap.w rd, rs2, (rs1) 原子交换
amoadd.w rd, rs2, (rs1) 原子加法
amoxor.w rd, rs2, (rs1) 原子异或
amoand.w rd, rs2, (rs1) 原子与
amoor.w rd, rs2, (rs1) 原子或
amomin.w rd, rs2, (rs1) 原子有符号最小值
amomax.w rd, rs2, (rs1) 原子有符号最大值
amominu.w rd, rs2, (rs1) 原子无符号最小值
amomaxu.w rd, rs2, (rs1) 原子无符号最大值

每条 AMO 指令的操作都是：*rs1 = op(*rs1, rs2)，同时将旧值返回到 rd。

五、浮点扩展 (F + D)

5.1 浮点寄存器

F/D 扩展添加 32 个 32 位浮点寄存器 f0-f31。D 扩展使用相同的寄存器，以偶数对（f0-f1, f2-f3…）存储双精度浮点数。

5.2 浮点指令分类

类别 单精度 (F) 双精度 (D) 说明
加法 fadd.s fadd.d 浮点加法
减法 fsub.s fsub.d 浮点减法
乘法 fmul.s fmul.d 浮点乘法
除法 fdiv.s fdiv.d 浮点除法
平方根 fsqrt.s fsqrt.d 平方根
乘加 fmadd.s fmadd.d 融合乘加
比较 feq/flt/fle 同左 浮点比较
符号注入 fsgnj/fsgnjn/fsgnjx 同左 符号位操作
类型转换 fcvt.s.w 等 fcvt.d.w 等 int ↔ float
加载 flw fld 从内存加载
存储 fsw fsd 存储到内存

5.3 融合乘加 (FMA)

FMA（Fused Multiply-Add）以无限精度执行乘法后精确舍入一次——比先乘后加精度更高且速度更快，常用于矩阵运算和信号处理。

六、压缩指令扩展 (C)

RISC-V 的 C 扩展（RV64GC 中的 C）将常用指令压缩为 16 位，大幅提升代码密度——在嵌入式场景中典型节省 25%-30% 的代码空间。

6.1 核心设计原则

  • 每条压缩指令都对应一条标准 32 位指令（C 是 32 位 ISA 的透明编码层）
  • 压缩指令仅操作 ABI 的 8 个常用寄存器（x8-x15）和 x0、sp、ra
  • 立即数范围缩小
  • 所有 16 位指令必须对齐 2 字节

6.2 压缩指令示例

16位指令 对应 32位 功能
c.add rd, rs2 add 加法
c.addi rd, imm addi 加立即数
c.addi16sp imm addi x2, x2, imm SP 加立即数
c.li rd, imm addi rd, x0, imm 加载立即数
c.lw rd, offset(rs1) lw 加载字
c.sw rs2, offset(rs1) sw 存储字
c.j offset jal x0, offset 无条件跳转
c.jal offset jal x1, offset 调用
c.jr rs1 jalr x0, 0(rs1) 寄存器跳转
c.ret jalr x0, 0(ra) 函数返回
c.beqz rs1, offset beq 相等零跳转
c.bnez rs1, offset bne 不等零跳转

七、特权架构

RISC-V 定义了清晰的特权级别体系：

7.1 特权级别

级别 名称 用途
0 U-mode (User) 用户态应用程序
1 S-mode (Supervisor) 操作系统内核
2 H-mode (Hypervisor) 虚拟机监控器 (VMM)
3 M-mode (Machine) 固件 / 底层管理

所有实现必须支持 M-mode，其他模式为可选。

7.2 控制与状态寄存器 (CSR)

CSR 用于控制处理器状态和进行特权级别切换。关键寄存器：

CSR 地址 功能
mstatus 0x300 机器状态（全局中断使能等）
mtvec 0x305 机器陷阱向量基址
mepc 0x341 机器异常程序计数器
mcause 0x342 机器异常原因
mtval 0x343 机器陷阱值（如访问地址）
mie 0x304 机器中断使能
mip 0x344 机器中断挂起
mhartid 0xF14 硬件线程 ID
satp 0x180 页表基址寄存器 (S-mode)

7.3 异常与中断

RISC-V 采用统一的”陷阱”机制处理中断和异常：

  1. 发生陷阱时，硬件将 PC 保存到 mepc，原因写入 mcause
  2. 跳转到 mtvec 指向的陷阱处理程序
  3. 处理完毕后，mret 指令从 mepc 恢复 PC

九、扩展 RV64I

RV64I 是 RV32I 的 64 位版本，核心变化：

新增指令 功能
addiw 立即数加法（32位变体，符号扩展）
slliw/srliw/sraiw 移位指令（32位变体）
addw/subw/sllw/srlw/sraw R-type 运算（32位变体）
ld 加载双字（64位）
sd 存储双字（64位）
lwu 加载无符号字（零扩展至 64 位）

RV64I 中，w 后缀指令仅操作寄存器低 32 位，结果符号扩展到 64 位。lwu 和 ld/sd 体现了从 32 位到 64 位寻址的扩展。

10.1 硬件

芯片 设计者 特点

10.2 软件

  • Linux Kernel：从 5.x 开始原生支持
  • QEMU：完善的模拟器支持
  • FreeRTOS：实时操作系统移植
  • Android：Google 正在推动 Android 对 RISC-V 的官方支持
  • Debian/Ubuntu：正在构建 RISC-V 官方移植

结语

RISC-V 的核心优势在于模块化 + 开放性。相比 x86 的历史包袱和 ARM 的高额授权费，RISC-V 为学术界、初创公司乃至个人爱好者都提供了一片没有禁入标志的乐园。从 $0.10 的单片机到数据中心级服务器，从嵌入式 RTOS 到 Android 移动生态，RISC-V 的版图正在以惊人的速度扩张。无论你是计算机体系结构的学生、嵌入式工程师，还是对处理器设计有兴趣的爱好者，RISC-V 都值得你深入研究。
